# PRD-Комплектующие рабочей станции

**Дата:** 2026-11-11

## Цель
Вести учёт отдельных единиц техники, из которых состоит актив «Рабочая станция» (монитор, системный блок, принтер, клавиатура, мышь, ДБЖ), чтобы всегда было видно, где какая единица находится, у кого и исправна ли она, даже когда комплект разбит между людьми и складом.

## Пользовательские сценарии
1. S1. admin -> открывает карточку актива категории «Рабочая станция» и добавляет комплектующую (вид, серийный номер, краткое описание, место, держатель, исправность) -> комплектующая появляется в составе станции.
2. S2. admin -> добавляет несколько мониторов одной станции (2 или 3) -> каждый монитор учитывается отдельной записью со своим серийным номером.
3. S3. admin -> пропускает вид комплектующей (например, нет принтера) -> станция сохраняется, пустой вид не считается ошибкой.
4. S4. editor -> меняет место и держателя одного монитора станции (например, переносит на склад) -> остальные комплектующие станции остаются у прежнего держателя.
5. S5. editor -> смотрит единицу, лежащую на складе или у другого человека -> видит инвентарный номер комплекта (он общий с рабочей станцией) и станцию, к которой единица относится.
6. S6. admin -> открывает карточку станции -> видит состав по видам: Монитор (1-3), ПК (системный блок), Принтер, Клавиатура, Мышь, ДБЖ; у каждой единицы серийный номер (если есть), держатель, место, краткое описание, исправна/неисправна.
7. S7. editor -> ищет по виду «Монитор» в общем списке -> видит все мониторы, включая те, что лежат на складе, независимо от станции.
8. S8. viewer -> открывает карточку станции и общий список по виду -> видит данные, но не может их менять.

9. S9. любой пользователь -> открывает «Огляд майна» -> видит отдельные плитки комплектующих на складах, не смешанные с плитками самостоятельных активов.

## Скоуп
- Отдельные записи комплектующих, привязанные к станции; виды: монитор (до 3 на станцию), ПК (системный блок), ноутбук, принтер, клавиатура, мышь, ДБЖ.
- Поля комплектующей: вид, серийный номер (необязательный, у единиц одного комплекта разные), краткое описание (свободный текст, заметки только по этой единице), место, держатель, признак «исправна / неисправна». Отдельного инвентарного номера у единицы нет: на весь комплект один номер, как у станции.
- Блок «Состав» на карточке станции, сгруппированный по видам. Подменю/раздел комплектующих существует только для активов категории «Рабочая станция»; у остальных категорий его нет.
- Общий список комплектующих с поиском и фильтром по виду, включая единицы на складе.
- Ручное добавление и редактирование состава.
- Доступ по ролям как у остальных данных.
- Отдельные плитки на «Огляд майна»: ПК, Монітор, Ноутбук, ДБЖ, Принтер (комплектующие) — количество единиц на Склад-327 и Склад-915, независимо от исправности; существующие плитки активов не меняются.

## Не в скоупе
- Автоматическая разбивка существующих станций (из текста названия или импорта).
- Связь исправности с 9 статусами актива.
- Документы движения (поступление, передача, списание) для отдельных комплектующих.
- Импорт и экспорт комплектующих.

## Технические ограничения
- Работает на SQLite (разработка) и MySQL (прод); без специфичного для движка SQL.
- Интерфейс, подписи и бизнес-комментарии на украинском.
- Роли: admin — полный доступ; editor — только по активам, где он ответственное лицо (`custodian`); viewer — только чтение. Для новой сущности нужна политика доступа и такая же фильтрация.
- Рабочая станция определяется категорией актива (тип «Рабочая станция»), отдельной отметки нет.
- Единица всегда относится к станции; она может находиться на складе или у другого человека, но остаётся частью комплекта и в его учёте.
- Если вся станция у одного человека, место и держатель комплектующих заполнять не обязательно (используются данные станции).
- Существующее поведение актива (статусы, документы, длинные названия через краткое имя) не должно ломаться.
- Новый раздел добавляется в smoke-тест e2e; нужны PHPUnit-тесты логики и Playwright-тесты интерфейса.

## Критерии готовности
- [x] S1: admin добавляет комплектующую со всеми полями, после сохранения она отображается в составе станции.
- [x] S2: у одной станции можно создать 3 монитора с разными серийными номерами; все три видны в составе.
- [x] S3: станция без принтера и без мыши сохраняется и открывается без ошибок; пустые виды не выводятся как ошибки.
- [x] S3: серийный номер, описание, место и держатель можно оставить пустыми; при пустых месте и держателе показываются данные станции.
- [x] S4: смена места и держателя одного монитора не меняет данные остальных комплектующих.
- [x] S5: у единицы на складе или у другого человека в общем списке видны инвентарный номер комплекта (совпадает с номером станции) и станция.
- [x] Раздел комплектующих и блок «Состав» доступны только для активов категории «Рабочая станция»; у актива другой категории их нет.
- [x] Заметка единицы видна только у неё и не отображается у других единиц и станций.
- [x] S6: карточка станции показывает комплектующие по видам, у каждой — серийный номер, держатель, место, описание, «исправна»/«неисправна».
- [x] S7: поиск по виду «Монитор» возвращает мониторы всех станций, включая лежащие на складе; поиск по серийному номеру находит единицу.
- [ ] S8: viewer не видит кнопок создания, редактирования и удаления комплектующих; прямой запрос на изменение отклоняется.
- [ ] Доступ: editor видит и меняет комплектующие только станций, где он ответственное лицо; чужие недоступны.
- [ ] Удаление или смена станции не оставляет комплектующих без понятной связи (поведение зафиксировано и проверено тестом).
- [x] S9: плитки «ПК / Монітор / Ноутбук / ДБЖ / Принтер (комплектуючі)» показывают число единиц с локацией Склад-327 или Склад-915 (исправных и неисправных); единицы в других локациях и без локации не считаются; плитки активов не меняются.
- [ ] Миграция проходит на SQLite и MySQL; все PHPUnit и e2e тесты (включая новый раздел в smoke) проходят.
