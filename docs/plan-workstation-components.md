## Фаза 1: Добавление комплектующей на карточке станции (Tracer Bullet)

**Статус:** [x] выполнена 2026-11-11 (коммит: «Phase 1: workstation components tab on the asset card»)

### Цель
admin открывает карточку актива категории «Рабочая станция», добавляет комплектующую (в том числе три монитора) и видит её в списке состава; у активов других категорий этого блока нет.

### Затрагивает
Бекенд, Фронтенд, База данных

### Задачи
- **Задача 1.** Данные комплектующей: вид (монитор, ПК, принтер, клавиатура, мышь, ДБЖ), серийный номер, краткое описание (текст), место, держатель, признак «исправна / неисправна», связь со станцией; миграция, совместимая с SQLite и MySQL, фабрика.
- **Задача 2.** Доступ admin к комплектующим (политика, в этой фазе только admin).
- **Задача 3.** Вкладка «Комплектующі» на карточке актива с таблицей единиц и действием «Додати» (все поля формы, необязательные кроме вида), украинские подписи.
- **Задача 4.** Вкладка показывается только для активов с типом «Рабочая станция»; у остальных типов её нет.

### Тесты
- PHPUnit: создание комплектующей со всеми полями; три монитора с разными серийными у одной станции; вкладка/доступ только у типа «Рабочая станция»; политика пускает admin.
- Playwright: admin на карточке станции из `E2ESeeder` добавляет монитор, он появляется в таблице; на карточке обычного актива вкладки нет. Станция в `E2ESeeder` получает тип «Рабочая станция».

### Готово когда
admin на карточке станции создаёт 3 монитора с разными серийными, все три видны в таблице; на карточке актива другого типа вкладки нет; новые тесты и вся pre-commit проверка проходят.

**Закрывает критерии PRD:** C1, C2, C7

## Фаза 2: Состав станции по видам и правка единицы

**Статус:** [x] выполнена 2026-11-11 (коммит: «Phase 2: workstation composition by kind»)

### Цель
Карточка станции показывает состав сгруппированным по видам с полными данными единицы; единицу можно править независимо от остальных.

### Затрагивает
Бекенд, Фронтенд

### Задачи
- **Задача 1.** Блок «Состав» на карточке станции: группы по видам в порядке монитор, ПК, принтер, клавиатура, мышь, ДБЖ; у единицы серийный номер, держатель, место, описание, «справна / несправна»; виды без единиц не выводятся и не дают ошибок.
- **Задача 2.** Если место или держатель единицы пусты, показываются данные станции.
- **Задача 3.** Редактирование единицы (место, держатель, исправность, серийный, описание) не затрагивает другие единицы.

### Тесты
- PHPUnit: смена места/держателя одного монитора не меняет остальные; пустые поля берут значения станции; заметка одной единицы не попадает к другим; станция без принтера и мыши открывается.
- Playwright: карточка станции показывает группы и поля единиц; станция без принтера и мыши открывается без ошибок и JS-ошибок; правка монитора не меняет остальные.

### Готово когда
Карточка станции с 3 мониторами и без принтера показывает 3 монитора и остальные виды, без пустых групп; перенос одного монитора на склад не меняет держателя других единиц; новые тесты и вся pre-commit проверка проходят.

**Закрывает критерии PRD:** C3, C4, C5, C8, C9

## Фаза 3: Общий список комплектующих

**Статус:** [x] выполнена 2026-11-11 (коммит: «Phase 3: general components list»)

### Цель
Все единицы техники, включая лежащие на складе, находятся одним поиском по виду и серийному номеру.

### Затрагивает
Бекенд, Фронтенд

### Задачи
- **Задача 1.** Раздел «Комплектующі» в меню (группа «Облік майна») со списком всех единиц: вид, серийный, описание, место, держатель, исправность, станция и её инвентарный номер.
- **Задача 2.** Фильтр по виду, поиск по серийному номеру и описанию.
- **Задача 3.** Строка ведёт на карточку станции единицы.

### Тесты
- PHPUnit: список содержит мониторы разных станций, включая со складским местом; фильтр по виду и поиск по серийному; инвентарный номер единицы равен номеру станции.
- Playwright: раздел открывается без 5xx и JS-ошибок (добавить в `PAGES` в `smoke.spec.js`); фильтр «Монитор» показывает мониторы нескольких станций; поиск по серийному находит единицу; видны инвентарный номер и станция.

### Готово когда
Фильтр «Монитор» возвращает мониторы всех станций (в том числе на складе), поиск по серийному находит ровно эту единицу и показывает инвентарный номер и станцию; новые тесты и вся pre-commit проверка проходят.

**Закрывает критерии PRD:** C6, C10

## Фаза 4: Доступ по ролям и целостность данных

**Статус:** [ ] не выполнена

### Цель
Роли ограничены как у остального учёта, удаление станции не оставляет бесхозных единиц; изменения проверены на обеих СУБД.

### Затрагивает
Бекенд, Фронтенд, База данных

### Задачи
- **Задача 1.** viewer: только чтение (нет кнопок создания, правки, удаления; прямые запросы отклоняются).
- **Задача 2.** editor: видит и меняет единицы только станций, где он ответственное лицо, и в общем списке, и на карточке.
- **Задача 3.** Поведение при удалении станции зафиксировано правилом на уровне данных и проверено.
- **Задача 4.** Проверка миграции на SQLite и MySQL.

### Тесты
- PHPUnit: политика для admin/editor/viewer; область видимости editor в общем списке; удаление станции; прямая запись от viewer отклоняется.
- Playwright: у editor (из `E2ESeeder`) нет единиц чужой станции и есть единицы своей; viewer не видит кнопок изменения.

### Готово когда
viewer не может создать/изменить/удалить единицу, editor видит только единицы своих станций, удаление станции проверено тестом, миграция проходит на SQLite и MySQL; все PHPUnit и e2e тесты проходят вместе с pre-commit проверкой.

**Закрывает критерии PRD:** C11, C12, C13, C14

## Фаза 5: Плитки комплектующих на «Огляд майна»

**Статус:** [x] выполнена 2026-11-11 (коммит: «Phase 5: warehouse tiles for workstation components»)

### Цель
На дашборде видно, сколько комплектующих каждого вида лежит на складах, отдельно от самостоятельных активов.

### Затрагивает
Бекенд, Фронтенд

### Задачи
- **Задача 1.** Вид комплектующей «Ноутбук».
- **Задача 2.** Блок плиток «Комплектуючі на складах»: ПК, Монітор, Ноутбук, ДБЖ, Принтер (комплектуючі), один запрос, всегда пять плиток (`0 шт` если пусто), с описанием что считается.
- **Задача 3.** Блок стоит на дашборде сразу после плиток активов.

### Тесты
- PHPUnit: считаются единицы на Склад-327 и Склад-915 независимо от исправности; другие локации и пустая локация не считаются; плитки активов не меняются; порядок виджетов и значения сортировки.
- Playwright: на дашборде есть блок с пятью плитками и ожидаемыми числами из `E2ESeeder`; плитки активов прежние.

### Готово когда
При монитор-комплектующей на Склад-915 плитка «Монітор (комплектуючі)» показывает «1 шт», плитка «Монітор» (активы) не меняется; новые тесты и вся pre-commit проверка проходят.

**Закрывает критерии PRD:** C15
