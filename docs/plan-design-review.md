## Принятые решения

- Плитки склада остаются как есть: захардкоженные склады `Склад-327` и `Склад-915`, четыре типа, данные для всех (без скоупа по роли).
- Все остальные виджеты тоже остаются глобальными. Скоуп по роли применяется только к новому блоку «Потребує уваги».
- Дашборд называется «Огляд майна» (заголовок страницы и пункт меню).
- Распределение по статусам: горизонтальные бары вместо кольца.
- Вкладки истории на карточке актива: счётчики и пустое состояние. CSS в `theme.css` не трогаем.
- Очередь «Потребує уваги»: 5 статусов, скоуп по роли.

## Правила выполнения

- Один шаг даёт один результат, который можно проверить и протестировать.
- Один шаг — один коммит, проходящий pre-commit хук (Pint, ESLint, PHPUnit, vite build, Playwright).
- В каждом шаге добавляется запись в журнал `CLAUDE.md` (на английском).
- Запросы к БД должны работать на SQLite и MySQL. Группировку по месяцам делаем в PHP, без `DATE_FORMAT` и `strftime`.

**Зачем.** В проекте есть только `UserFactory`, а e2e-база почти пустая. Без данных нельзя ни тестировать виджеты, ни оценить дизайн.

4. Расширяем `E2ESeeder`:

   - по 1–2 документа на актив;

**Готово, когда:**

- В e2e-базе виден разнообразный дашборд и список.

**Тесты:**

## Шаг 1. Карточка актива: идентичность и плотность

**Статус:** [ ] не выполнен

**Что делаем:**
1. `ViewAsset::getHeading()` возвращает название, `getSubheading()` — `№ {inventory_number}`.
2. В `AssetInfolist` делаем шапку из двух зон через `Flex`: слева название, инвентарный номер (моноширинный, копируемый) и крупный статус, справа локация, тип и год.
3. Секция «Відповідальність і ідентифікація» с `inlineLabel()` в 2 колонки: МВО, Користувач, серійний номер, примітки.
4. Секция «Службова інформація» свёрнута: создано и обновлено через `since()` с подсказкой полной датой.
5. Исправляем «2 024»: убираем `->numeric()`.
6. `placeholder('Не призначено')` оставляем только у МВО, Користувач и примітки.

**Готово, когда:**
- Название и статус видны без прокрутки в верхней зоне.
- Год показывается как `2024`.
- Карточка заметно ниже прежних ~370px высоты на 4 факта.

**Тесты:**
- PHPUnit (Livewire): `Livewire::test(ViewAsset::class)` проверяет heading и subheading, год `2024` и отсутствие `2 024`. Для editor чужой актив недоступен (404/403).
- Playwright: на `/admin/assets/{id}` в заголовке есть название, бейдж статуса находится в первой зоне, кнопка копирования номера присутствует.

## Шаг 7. Виджет «Потребує уваги»

**Статус:** [ ] не выполнен

**Что делаем:**
1. Новый `AssetsNeedingAction` (`TableWidget`, во всю ширину, пагинация 5). Источник — `AssetResource::getEloquentQuery()`, то есть editor видит только свои активы.
2. Статусы: `NOT_PUT_IN_TO_OPERATION`, `TRANSFERRING`, `WRITING_OFF`, `REPAIR`, `LOST`.
3. Колонки: инвентарный номер (моноширинный, копируемый), название, статус бейджем, «Очікує» (`since()` от `updated_at`). Строка ведёт на карточку актива.
4. Удаляем мёртвый `NotIntroducedAssets` (отключён через `canView() = false` и закомментирован в панели) и регистрируем новый.

**Готово, когда:**
- Admin и viewer видят все такие активы, editor только свои.
- Клик по строке открывает карточку из шага 1.

**Тесты:**
- PHPUnit (Livewire): admin видит активы всех 5 статусов и не видит `balance`; editor видит только `custodian_id` своего сотрудника; viewer видит всех.
- Playwright: виджет виден, клик по строке ведёт на `/admin/assets/{id}`. Отдельный прогон под `editor@e2e.test` проверяет, что чужих активов нет.
